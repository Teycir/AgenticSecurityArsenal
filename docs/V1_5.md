# v1.5 — Stateful Investigation Engine

## Purpose

The v1.5 engine moves the arsenal from isolated capability calls toward a stateful, evidence-led investigation workflow. It gives an AI agent a session document that it can update and persist between calls.

## Lifecycle

1. Create a session from normalized v1.4 reports and a valid exact-origin scope manifest.
2. Review the generated unverified hypotheses and low-confidence candidate correlations.
3. Request the next queued step. The engine returns instructions; it does not execute them.
4. Perform only an independently authorized, benign check using suitable tooling.
5. Record `observed`, `not_observed`, or `inconclusive`, with a note and optional evidence.
6. Request the next action or produce a report for human review.

## MCP state contract

The session is returned as a JSON object. Pass its latest serialized form as `session_json` to `investigation_next`, `investigation_record`, or `investigation_report`. Persist the returned updated session after every record operation.

## Candidate attack paths

The current correlator groups observations only when they share an explicit host/target value. The relationship is labelled `shared_target_context_only`, confidence is `low`, and status is `candidate_only`. It does not infer a vulnerability chain or prove that one finding enables another.

## Result semantics

- `observed`: the supplied check observed the described behavior; this is not vulnerability confirmation.
- `not_observed`: the behavior was not reproduced by this check; it does not prove absence.
- `inconclusive`: evidence or conditions were insufficient.

A step can be recorded only once. The engine refuses unknown step IDs, unsupported outcomes, empty notes, and duplicate results.

## Safety limits

- Session creation validates an unexpired authorization manifest and exact target origin.
- Session creation, action selection and reporting are offline.
- No automatic exploitation, arbitrary shell, crawling, fuzzing, credential access, destructive methods or data extraction are included.
- The engine does not perform the validation described by a queued step.
- Session JSON is mutable operator-managed state, not a signed or tamper-proof record.
